一、 專案概述 (Project Overview)
產品名稱： 「盲盒式」社團與活動人脈推薦助理 (MVP 階段)

目標受眾： 患有「選擇障礙」、渴望擴展人脈與充實履歷的大學生。

核心價值： 降噪與聚焦。透過 AI 分析，將龐雜的校內外資訊收斂為每日 3 筆高含金量的專屬推薦。

二、 系統架構與技術選型 (System Architecture)
考量到開發敏捷度與 AI 應用的契合度，建議採用以下技術棧：

前端 (Frontend)： React.js 或 Vue.js（若想快速驗證，也可使用 Streamlit，完全基於 Python，極度符合 antigravity 的精神）。

後端 (Backend)： Python FastAPI（輕量、異步處理快，適合串接 AI API）或 Django。

資料庫 (Database)： PostgreSQL（儲存用戶設定與活動靜態資料）搭配 Vector Database（如 Chroma 或 Pinecone，用於將活動內容與用戶興趣做語意向量比對）。

AI 模型 (AI Engine)： Google Gemini API（負責自然語言理解、標籤萃取與生成 Markdown 回覆）。

三、 核心功能模組 (Core Modules)
1. 用戶需求對齊模組 (Onboarding & Profiling)
對話式引導： 系統開場即要求用戶輸入一段話描述背景。

動態標籤萃取： AI 在接收輸入後，自動解析出 現有優勢、技能缺口、潛在興趣 三類標籤。

範例情境： 當用戶輸入「我是商管學生，未來想做行銷，平常喜歡自省，對高齡社會創新專案有興趣，也略懂 Python」。

標籤生成： [商管]、[行銷企劃]、[高齡創新]、[Python 數據分析]、[自我探索]。

標籤確認面板： 以前端 UI 呈現這些標籤，讓用戶可點擊微調、新增或刪除，確保 AI 理解無誤。

2. 活動資料庫與處理模組 (Event Data Pipeline)
資料來源： 定期爬取校內公告、Accupass、Blink 等大學生常用活動平台。

資料清洗與向量化： 將抓取到的活動簡介交由 AI 總結為「一句話介紹」，並轉換為向量儲存，以便後續與用戶標籤進行高維度比對。

3. 盲盒推薦引擎 (Blind Box Engine)
推薦邏輯 (Rule-based + AI)： 嚴格限制每次查詢僅從資料庫中撈取 3 筆資料，分別對應三個維度：

💼 背景補強： 搜尋與「主修/職涯目標（如：商業競賽、量化投資工作坊）」高度重疊的活動。

🌱 興趣延伸： 搜尋與「次要興趣（如：高齡照護志工、烘焙市集招商）」相關的活動。

🎁 盲盒驚喜： 故意加入一點隨機性或跨領域權重（如：與商管無關的科技藝術展覽、或偏向心理學與自我探索的深夜講座），擴展用戶舒適圈。

4. 格式化輸出與互動介面 (UI / Output Formatting)
Markdown 渲染： 前端需支援 Markdown 語法解析，完美呈現您設定的 🎯 你的專屬活動盲盒已送達！ 格式。

「點擊進入」機制： 推薦文字中隱藏詳細網址，前端實作一個「展開」或「詳細資訊」的按鈕，用戶點擊後才顯示具體的時間、地點與報名連結，營造開盲盒的儀式感。

強制輸出限制： 無論用戶如何詢問，單次回覆的活動數量 MAX_EVENTS = 3。

語氣設定 (Persona)： 系統提示詞需定義 AI 為「一位經驗豐富、懂大學生生態的學長姐」，用語需俐落、直擊痛點（例如：「這場活動能幫你補齊履歷上缺乏的實戰數據分析經驗」）。
